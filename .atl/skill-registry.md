## Compact Rules (inject into sub-agent prompts as "## Project Standards")

### Database / Postgres / Supabase (touching queries, schema, migrations, RLS)
- This is a MULTI-TENANT app with Postgres RLS enabled (migrations 36-42). NEVER
  disable RLS or tenant isolation to make a feature work.
- Tenant context is set per-request via TenantInterceptor (`app.current_tenant`)
  before any DB access; respect it in new repositories/queries.
- Prefer indexed lookups; avoid N+1 (see references/data-n-plus-one.md). Add FK
  indexes for new foreign keys.
- Schema/migrations go through TypeORM CLI migrations — never `synchronize`.
- Use lowercase identifiers, explicit constraints, and proper data types.

### NestJS backend conventions
- Feature-per-module under `backend/src/modules/<name>/` with `*.module.ts`,
  `*.controller.ts`, `*.service.ts`, `dto/`, `entities/`.
- Guards order matters: ThrottlerGuard → AuthGuard → ClientIsolationGuard.
  Use `@Public()` for unauthenticated routes; `@CurrentUser()` / `@CurrentClient()`.
- DTOs use class-validator; global ValidationPipe runs whitelist + forbid extras.
- Validate AI/user input through prompt-shield / sanitize-input pipe where relevant.
- No `any` in bootstrap/core paths.

### Frontend (Next.js 16 — breaking changes vs training data)
- This is NOT the Next.js in training data. Read `node_modules/next/dist/docs/`
  before writing frontend code. Heed deprecation notices.
- shadcn + Tailwind 4. Role-based routing: super_admin → /admin, client roles → /client.

### General
- Never run a build after changes (user rule).
- Conventional commits only; no AI attribution in commits.
